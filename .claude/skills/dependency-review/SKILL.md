# Dependency review

Dependabot opens update PRs on Mondays (see `.github/dependabot.yml`). This skill checks each one by actually running the project, not only by reading the changelog.

GitHub Actions does not currently start on this repo (runs end in `startup_failure`), so the checks below are the merge gate. If a PR does have check runs, a failing one blocks the merge.

## 1. Collect the PRs

List open PRs authored by `dependabot[bot]` in `JordiParraCrespo/cosmos-explorer`. For each, record:

- ecosystem (npm, gomod, github-actions, docker) and the packages and versions it changes;
- update type: **major** if any package changes its major version (for `0.x`, a minor change counts as major), otherwise **minor/patch**;
- whether it has merge conflicts. If it does, comment `@dependabot rebase` on it and skip it for this run.

Handle PRs one at a time, oldest first.

## 2. Verify each PR

Check out the PR branch and merge the current `main` into it locally (do not push that merge), so the test covers what would land.

Run whatever applies to the files the PR changes, and record pass, fail or not-run with the reason for each step:

| Changed | Checks |
|---|---|
| `package.json` / `pnpm-lock.yaml` | `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm typecheck`, `pnpm build`, then the explorer smoke test below |
| `apps/callisto` Go modules | in `apps/callisto`: `go build ./...`, `go vet ./...`, `make build`; `make test-unit stop-docker-test` if Docker is available (otherwise mark it not-run) |
| `packages/juno` Go modules | in `packages/juno`: `go build ./...`, `go test ./...`; then `go build ./...` in `apps/callisto` (it imports Juno) |
| `.github/workflows` | read the action's release notes for breaking input or output changes; confirm every `with:` key we pass still exists |
| `docker/` | `docker build` the changed Dockerfile if Docker is available; otherwise read the image's release notes and mark it not-run |

**Explorer smoke test** (for any npm change):

```bash
cp apps/explorer/.env.example apps/explorer/.env   # NETWORK=testnet
(cd apps/explorer && PORT=3100 pnpm start &)        # after pnpm build
node scripts/smoke-explorer.mjs http://localhost:3100
```

The script loads every list page plus one detail page of each kind against the live testnet indexer. It fails on HTTP errors, the error boundary, or uncaught browser exceptions. Stop the server afterwards.

If the smoke test fails, run it once on `main` too. If `main` fails the same way, the failure is the testnet backend's, not the PR's: say so in the report and do not merge that PR this run.

For a major update, also read the package's changelog or migration guide and search the code for the APIs it changes.

## 3. Fix what breaks

If a check fails because our code needs adapting to the new version:

- make the smallest fix that follows the repo's conventions (see `CLAUDE.md`), re-run every check from step 2, and push it to the Dependabot branch as a separate commit;
- if the fix is not small (it touches many files, changes behaviour, or needs a design decision), do not push. Describe the breakage and the fix you would make in the report instead.

## 4. Merge

Squash-merge a PR only when **all** of these hold:

- the update is minor/patch (never merge a major, never merge a docker or github-actions major);
- every applicable check in step 2 passed and none was skipped for a reason other than "does not apply";
- you did not push any code to it in this run (a PR you fixed waits for a human);
- it has no failing GitHub check runs and no unresolved review comments.

After each merge, Dependabot rebases the other PRs. Re-check mergeability before the next merge, and skip any PR that now conflicts.

Do not merge anything else, and never edit `.github/dependabot.yml`, workflows, or branch protection to get a PR through.

## 5. Report

On each PR you looked at, post one comment:

```
**Dependency review: <Merged | Ready, needs human merge | Fixed, needs review | Blocked>**

| Check | Result |
|---|---|
| install / lint / typecheck / build | ✅ / ❌ / not run (why) |
| explorer smoke test (testnet) | ✅ 10/10 pages / ❌ <failing pages> |
| Go build / tests | ... |

<For majors or failures: what changed upstream, what broke, what was fixed or what is needed.>

---
_Generated by [Claude Code](https://claude.ai/code)_
```

End the run with a short summary listing each PR, its outcome and its link, as your final message. Keep it short, because it is what the owner gets as a notification.
